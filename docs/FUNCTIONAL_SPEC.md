# TradeLoop — Functional Specification

**Scope:** a small commodity trading and risk management (CTRM) system for one trading entity
(Meridian Trading Ltd, fictional) that trades German power, TTF gas and Brent crude as physical
forwards and fixed-for-floating swaps. It covers the trade lifecycle end to end:
**capture → confirm → value and risk → settle → reconcile → report**.

**Users**

| Role | What they need from the system |
|---|---|
| Trader | Book a deal quickly; be stopped from an obvious keying error |
| Middle office (risk) | Positions, mark-to-market, daily P&L explain, VaR, credit limits |
| Back office (operations) | Match confirmations, raise invoices, reconcile counterparty statements |
| Compliance | A complete audit trail and a regulatory transaction report |

**Out of scope:** options, scheduling/nominations, real market-data feeds, payments, multi-entity
accounting. Market data is synthetic and seeded (see `tradeloop/market.py`).

## Requirements

| ID | Requirement | Rules / acceptance criteria | UAT |
|---|---|---|---|
| FR-01 | Capture a trade with reference-data checks | VR-01 mandatory fields and unique ID; VR-02 known commodity, product and side; VR-03 known, active counterparty | UAT-01–03 |
| FR-02 | Check the economics of a ticket | VR-04 quantity and price > 0; VR-05 valid YYYY-MM period, end ≥ start; VR-06 trade date ≤ as-of date | UAT-04–05 |
| FR-03 | Catch fat-finger prices | VR-07: reject if price is > 30% from the strip-average forward curve on the trade date; warn above 15% | UAT-06–07 |
| FR-04 | Amend a trade | Only economic fields; new version, old versions kept; re-validated; status returns to VALIDATED so it must be re-confirmed | UAT-08 |
| FR-05 | Cancel a trade | Allowed before settlement; cancelled trades drop out of positions, risk and settlement; no further actions allowed | UAT-09–10 |
| FR-06 | Audit trail | Every capture, amend, confirm, cancel and settle logged with time, user, version and before/after values | UAT-11 |
| FR-07 | Match counterparty confirmations | Read free-text confirmations in 3 layouts; extract 8 economic fields; auto-confirm only on a full match; otherwise MISMATCH (named fields) or UNREADABLE → exception queue | UAT-12–14 |
| FR-08 | Positions | Net quantity by book, commodity and delivery month; delivered months roll off | UAT-15 |
| FR-09 | Mark-to-market and P&L explain | MtM in USD, discounted; day-on-day P&L split into curve move and new trades, with nothing unexplained | UAT-16 |
| FR-10 | Market risk | 1-day historical-simulation VaR at 95% and 99% on a 250-day window, total and by commodity | UAT-17 |
| FR-11 | Credit risk | Exposure = positive MtM + unpaid receivables, against each counterparty limit; WARN > 80%, BREACH > 100% | UAT-18 |
| FR-12 | Settlement | Physical: quantity × fixed price. Swap: quantity × (monthly average index − fixed). Netting by counterparty, month and currency | UAT-19–20 |
| FR-13 | Reconcile counterparty statements | Match on trade ID and month; classify AMOUNT, QUANTITY, MISSING_AT_CPTY, MISSING_IN_OURS, DUPLICATE; 0.01 tolerance | UAT-21–22 |
| FR-14 | Regulatory transaction report | One record per lifecycle event (N/M/C) with a stable UTI; checks RP-01 to RP-05 (empty fields, LEI format, duplicate NEW, event before NEW, quantity) | UAT-23–24 |
| FR-15 | REST API | All functions above available over HTTP (FastAPI, OpenAPI docs at `/docs`) | `tests/test_reporting_api_scenario.py` |

## Trade lifecycle

```
              confirm               settle
 VALIDATED ───────────► CONFIRMED ────────► SETTLED
   ▲   │                   │
   │   └──── cancel ───────┴──────────► CANCELLED
   └──── amend (new version; must be re-confirmed)
```

A ticket that fails VR-01 to VR-07 is never stored (it is rejected at capture).

## Key definitions

- **Strip price:** the average forward price over the delivery months, used as the fair price
  for a multi-month deal.
- **Monthly index (fixing):** the average of that month's daily prices; swaps settle against it.
- **Sign convention:** money is signed from our side: positive = we receive, negative = we pay.

## Known limitations

- Synthetic data. The confirmation documents and counterparty statements are generated by the same
  codebase that checks them, so the scenario results show the logic is consistent, not that it
  would reach the same accuracy on real counterparty paperwork.
- The regulatory report is REMIT-style and simplified; it is not a compliant ACER submission.
- Flat discount rate and fixed FX (EURUSD 1.08).
